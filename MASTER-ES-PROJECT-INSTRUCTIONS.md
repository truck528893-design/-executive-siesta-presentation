# Executive Siesta — Master Project Instructions

Status: Mandatory governing project instruction file

## Website image architecture

1. ALWAYS use the highest-resolution approved source image available for every Executive Siesta website display image.
2. NEVER use thumbnails, preview images, screenshots, heavily compressed derivatives, low-resolution copies, or tiny KEEPERS synchronization copies as website display assets.
3. KEEPERS is the approved resource/archive collection. It is not automatically the live website display folder.
4. Keep approved KEEPERS images synchronized to GitHub as resource assets for preservation and availability.
5. Maintain a separate, deliberately curated website display set selected from approved images. Only selected display files belong in the live rotation.
6. Before putting any image into the live website rotation, verify that it is the correct approved ES image and that the file used by the website is the highest-resolution version available.
7. Preserve image aspect ratio. Do not enlarge a low-resolution asset to fill the display area.

## Hero rotation behavior

1. Hold each hero image for 10 seconds.
2. Preload/decode the next image before beginning any transition.
3. Use a smooth crossfade with overlapping image layers. Never clear the visible image before the replacement is fully loaded.
4. There must be no white flash, blank frame, image disappearance, or loading flicker between images.
5. Preserve manual left/right swipe navigation on mobile.
6. Randomize the rotation and show each active image once before repeating a cycle.
7. For the current refinement stage, use only a limited curated set of approved images with clearly different backgrounds.

## Preservation and quality rule

Website optimization must never overwrite or degrade the master approved image. Any web-specific derivative must be made from the highest-resolution master, retain sufficient resolution for the target display, and remain separate from the master asset.
